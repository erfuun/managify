# Jump Hosts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A saved server can reach its host through one other saved server (`ssh -J`), for probes, runs, transfers and the shell.

**Architecture:** `inventory.Server` stores the jump server's ID. `sshx.Dialer` looks up the jump server through a `Lookup` hook, checks the one-hop rule, gets its live connection from the pool through a `Jump` hook, opens a `direct-tcpip` channel to the target and runs the usual handshake over it. A timer replaces the handshake deadline, which tunnel connections do not support.

**Tech Stack:** Go, golang.org/x/crypto/ssh v0.58.0, Bubble Tea.

**Spec:** `docs/superpowers/specs/2026-10-28-jump-host-design.md`

## Global Constraints

- One hop only. A jump server never has a `Jump` of its own.
- The jump is stored by server ID in YAML key `jump`, omitted when empty.
- Direct servers behave exactly as before; every existing test keeps passing unchanged, except where a task says to add a field to a fake.
- Task done = `go vet ./... && go test ./...` passes, plus `GOOS=linux go vet ./...`.
- Error and UI copy is verbatim from the spec's Validation, Errors and TUI sections.
- Commit messages: Conventional Commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Both hops need a prompt.** If neither host key is trusted yet, connecting to `db-1` first asks about `web-1`'s key, then about `db-1`'s, each prompt naming its own server. Covered by Task 4 `TestDialJumpPromptsJumpThenTarget`.
2. **Concurrent probe of jump and target.** The list probes `web-1` and `db-1` at the same moment. With the password set to "ask", only one `web-1` password prompt may appear. Covered by Task 4 `TestPoolJumpAndTargetShareOneDial`.
3. **SFTP through a jump.** Upload and download use `NewSFTP` on the tunnelled client, not just exec. Covered by Task 4 `TestDialJumpSFTP`.
4. **Jump connection dies.** After the pool evicts `web-1`, the next `Get(db-1)` must redial instead of returning a dead tunnel. Covered by Task 4 `TestEvictJumpDropsTunnel`.
5. **Hand-edited yaml pointing at a missing ID.** The dial returns the spec's message. It must neither panic nor dial `db-1` directly. Covered by Task 4 `TestDialJumpGuards`.

- [ ] **Step 1: Write failing tests** in `jump_test.go`. Each uses `testkit.NewEnv`, a jump server started with `Forward: true`, and a target. Both servers are added to `env.Inv`, and the target's `Jump` is the jump's ID. The target's `Host:Port` is the target listener address.

  - `TestDialJumpSFTP`: writing a file via `NewSFTP` on the target succeeds.
  - `TestPoolJumpAndTargetShareOneDial`: the jump is a password server set to ask, so the password is not saved. Concurrent `Pool.Get(jump)` and `Pool.Get(target)` raise exactly one `PromptPassword` request for the jump, and the jump's connection count is 1.
  - `TestDialJumpPromptsJumpThenTarget`: known_hosts is empty and both prompts are answered `yes`. The host-key prompts arrive in the order jump then target. The target's line in known_hosts is keyed by the target's `host:port`.

  - `TestDialJumpTargetRefused`: the target port is closed. The error is `*UnreachableError` with `Via == jump.Name` and `Reason == "connection refused"`.
  - `TestDialJumpSilentTarget`: the target is a raw listener that accepts and never writes, and `Dialer.Timeout` is 300 ms. The error is `*UnreachableError{Reason: "timeout"}` within 3 s.
  - `TestDialJumpGuards`: self-jump, jump to an ID not in the inventory, a jump whose server has its own `Jump`, and a cycle (a→b, b→a, with `Pool.Get(a)`) each return a `*JumpError` within 2 s, with no deadlock. The messages are `a server can't jump through itself`, `jump server not found` and `<name> itself jumps through <name>; only one hop is supported`.
  - `TestDialJumpNoHook`: a `Dialer` with a nil `Lookup` or `Jump` returns `JumpError{Err: errors.New("jump hosts are not set up")}` for a jumped server.
  - `TestCloseTargetKeepsJump`: closing the target client leaves `Pool.Get(jump)` returning the same live client.
  - `TestEvictJumpDropsTunnel`: after `Pool.Evict(jump.ID)`, the next `Pool.Get(target)` within 2 s returns a client different from the first, and `echo` works on it.

- [ ] **Step 2: Run** `go test ./internal/sshx/ -run Jump -timeout 60s`. It fails to compile.
- [ ] **Step 3: Implement** `Dial` in `dial.go`. Split today's body into `dialDirect` and `dialVia`. Both feed one shared `handshake(ctx, s, raw net.Conn, timeout) (Client, error)` that holds today's host-key, auth and `NewClientConn` code.
  - In `dialVia`, apply the guards in order: self-jump (`s.Jump == s.ID`), then `Lookup` miss, then a jump with its own `Jump`. Call `d.Jump` only after they all pass. Calling `Pool.Get` on the jump before the two-hop check would deadlock on a cycle such as a→b→a.
  - Return `ErrPromptCancelled` from `d.Jump` unwrapped. Wrap every other jump error in `JumpError`.
  - Bound `c.DialContext` with `context.WithTimeout(ctx, timeout)`. An `*ssh.OpenChannelError` with `Prohibited` becomes `JumpError{Err: ErrForwardingDenied}`. A `ConnectionFailed` with `Message` containing `refused` gets Reason `connection refused`. A deadline gets `timeout`. Anything else gets the `Message`. All of these are `UnreachableError{Addr: s.Addr(), Via: jump.Name}`.
  - Handshake errors over the tunnel go through `handshakeError`, whose `netError` call also sets `Via`.
