# Managify v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Managify, a Go TUI that stores a handful of Linux servers once and then opens shells, runs commands (with sudo), uploads/downloads files and shows status without retyping credentials.

**Architecture:** Plain-Go packages (`appdir`, `inventory`, `secrets`, `sshx`, `remote`, `outputs`, `job`, `snippets`, `friendly`) do all work and are tested headless. An in-process SSH/SFTP server (`sshtest`) backs the integration tests. `internal/tui` is the only package that imports Bubble Tea and renders the work through screens.

**Tech Stack:** Go 1.27, Bubble Tea v1.3.10 / Bubbles v1.0.0 / Lip Gloss v1.1.0, `golang.org/x/crypto` v0.58.0 (`ssh`, `knownhosts`, `agent`), `github.com/pkg/sftp` v1.13.12, `github.com/zalando/go-keyring` v0.2.8, `github.com/Microsoft/go-winio` v0.6.4, `golang.org/x/term` v0.47.0, `gopkg.in/yaml.v3` v3.0.1, `github.com/charmbracelet/x/exp/teatest` `v0.0.0-20261025003702-835ad0048169` (requires Bubble Tea v1; do not use `teatest/v2`).

**Spec:** `docs/superpowers/specs/2026-10-27-managify-design.md`

## Global Constraints

- Module path `managify`, `go 1.27` in `go.mod`. Standard `testing` only (no testify).
- Only `internal/tui` and `cmd/managify` import Bubble Tea / Bubbles / Lip Gloss.
- Target servers are Linux. Managify itself builds and tests green on Windows, macOS, Linux (`GOOS=linux go build ./...` and `GOOS=darwin go build ./...` must pass from Windows).
- Config dir = `os.UserConfigDir()/managify`. Data dir = `<home>/Managify` (holds `outputs/` and `downloads/`). Host keys = `<home>/.ssh/known_hosts`.
- Files created with mode `0600`, dirs with `0700`.
- Keychain service `managify`. Account = server ID (login password) or `<id>:sudo` (sudo password).
- Passwords and passphrases never appear in YAML, logs, output files or error text.
- Dial timeout 10 s. Keepalive every 30 s. Status refresh every 30 s. Commands have no timeout.
- Shell PTY term `xterm-256color`. Resize via SIGWINCH on Unix, polled every 250 ms on Windows.
- Host keys are always verified. TOFU only after explicit confirmation. A mismatch blocks the connection with no in-app override.
- Every task ends with `go vet ./...` and `go test ./...` green before commit.
- The race detector needs cgo+gcc, which this Windows machine lacks (`CGO_ENABLED=0`). Plan commands use plain `go test`. Run `go test -race ./...` in WSL or CI when available.
- A prompt the user is answering is never cut off by a timeout. Dial and probe deadlines are paused while a prompt is open.

## Review Focus

1. **Windows line endings in uploaded scripts.** A `deploy.sh` saved on Windows with CRLF fails remotely with `$'\r': command not found`. Upload must warn in the pane (test in Tasks 20 and 21).
2. **Server names that are illegal in Windows paths** (`web:1`, `a/b`, `con.`). Output and download dirs must use a sanitized name, never fail or escape the data dir (test in Task 16).
3. **Output with no trailing newline, or very long lines (>64 KiB).** The last partial line must still appear, and long lines must not abort the stream (test in Task 14).
4. **Remote paths with `~/` or a trailing `/`.** `~/x` means the home dir, and `dir/` means "into dir with the local file name" (test in Task 20).
5. **Editing a server's host/user/auth while a pooled connection exists.** The next action must dial the new target, not reuse the old connection (test in Task 10).

```go
type PromptKind int
const ( PromptPassword PromptKind = iota; PromptPassphrase; PromptSudo; PromptHostKey )
type PromptRequest struct {
	Server inventory.Server
	Kind   PromptKind
	Detail string // key path (passphrase) or "SHA256:…" fingerprint (host key)
}
type PromptReply struct { Text string; Accepted bool } // Accepted=false means cancelled / declined
var ErrPromptCancelled = errors.New("prompt cancelled")
type Prompter interface { Ask(ctx context.Context, r PromptRequest) (PromptReply, error) }

type Pending struct{ Req PromptRequest /* reply chan unexported */ }
func (p *Pending) Reply(r PromptReply)
type Queue struct{ C <-chan *Pending }
func NewQueue() *Queue
func (q *Queue) Ask(ctx context.Context, r PromptRequest) (PromptReply, error) // one outstanding at a time

type Creds struct { Store secrets.Store; Session *secrets.Session; Prompter Prompter }
func (c *Creds) LoginPassword(ctx context.Context, s inventory.Server) (string, error)
func (c *Creds) Passphrase(ctx context.Context, s inventory.Server, keyPath string) (string, error)
func (c *Creds) SudoPassword(ctx context.Context, s inventory.Server) (pw string, err error) // "" = NOPASSWD mode
func (c *Creds) ForgetLogin(s inventory.Server)
func (c *Creds) ForgetPassphrase(keyPath string)
func (c *Creds) ForgetSudo(s inventory.Server)
```

Rules:
- `Queue.Ask` holds a mutex for the whole exchange, so a second caller blocks until the first is replied. It returns `ErrPromptCancelled` when the reply is not accepted or ctx is done.
- `LoginPassword`: keychain if `SavePassword` → session → prompt (`PromptPassword`). A prompted value goes into the session, and also into the keychain when `SavePassword`.
- `Passphrase`: session key `"pass:"+keyPath` → prompt.
- `SudoPassword`: password-auth servers return `LoginPassword`. Key-auth servers: `saved` → keychain `SudoAccount`, prompting and storing if absent. `ask` → session `SudoAccount` key, else prompt (`PromptSudo`). `none`/`""` → `""`.

```go
func DefaultAgent() (agent.Agent, error) // Unix: SSH_AUTH_SOCK; Windows: winio.DialPipe(`\\.\pipe\openssh-ssh-agent`, &1s)
type AuthError struct { Server inventory.Server; Method inventory.Auth; PassphraseWrong bool }
type UnreachableError struct { Addr string; Reason string } // Reason: "timeout" | "connection refused" | other text
```

Auth chain:
- `key`: `ssh.PublicKeysCallback` that lazily returns agent signers (agent errors are ignored silently) plus the key-file signer. On `*ssh.PassphraseMissingError` → `Creds.Passphrase` → `ParsePrivateKeyWithPassphrase`. On `x509.IncorrectPasswordError` → `ForgetPassphrase` and `AuthError{PassphraseWrong:true}`.
- `password`: `ssh.PasswordCallback` and `ssh.KeyboardInteractive`, both answering with `Creds.LoginPassword`.

Errors:
- An "unable to authenticate" failure → `ForgetLogin` (password auth) and `*AuthError`.
- Net timeout or ctx deadline → `UnreachableError{Reason:"timeout"}`. A refused connection (`syscall.ECONNREFUSED`, or a message containing `refused`) → `"connection refused"`.
- Handshake deadline = Timeout, cleared after the handshake.
- `ssh.NewClientConn` runs the host-key, password and passphrase callbacks inside the handshake. The Dialer wraps the `net.Conn` (`pausableConn`) and every callback that prompts calls `pause()` (clears the deadline) before `Ask` and `resume()` (fresh `Timeout` deadline) after. Prompts get a ctx that is *not* derived from any probe timeout.
